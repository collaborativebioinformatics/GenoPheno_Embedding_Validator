## Testing pertubations of the Haplograph --> Evo2 genomic model to see what works best in particular settings.  

As a POC, builds a haploblock co-occurrence graph from the [1000 Genomes haplograph](https://data.haploblocks.org/haplograph/1000G/), turns its nodes into embeddings with Node2Vec, GNN or XGBoost, and fine-tunes Evo 2 (7B) on those embeddings.  We have fine tuned Evo2 embeddings generated by XGBoost without the graph, and established a baseline for comparison by fine tuning Evo2 with binary strings generated directly with unlinked haploblocks.  

For cancer, we prepared paired tumor/normal proteomics on the haploblocks and trained ProLM on synthetic data as a protein encoder (see [Proteomics](#proteomics-paired-tumornormal) below).  

For validation/comparison, we will use a 50/50 test train set to build and execute graphs at least two connections per node.  This will establish model consistency with respect to generation of and assignment to etiologies.

We will also test how many of the haploblocks in question have SNPs identified by GWAS consortia and other clinical tests.

In the future, for deleterious phenotypes we will assess how well individual etiologies respond to drugs.  For those that do not we can recommend them for data generation and drug development pipelines.  

For more see: [haploblocks.org](haploblocks.org)

## Usage

Run the scripts in order. Step 1 writes the graph to `haplograph/genome/`; steps 2–4 read and write there (change with `--graph-dir`).

```bash
python 1_build_graph.py                            # whole genome (or --chroms chr21,chr22)
python 2_ancestry_labels.py                        # needed for xgboost or --objective ancestry
python 3_node_embeddings.py --method node2vec      # or gnn / xgboost
python 4_finetune_evo2.py   --method node2vec      # --objective next (default) or ancestry
```

Add `--chroms chr21,chr22` to any step for a quick test run, and `--help` to see all options.

## Proteomics (paired tumor/normal)

*Status on 12 November 2026.* Proteomics is added as a second layer on the haploblocks, to test whether
proteins work better fused early (attached to their blocks before the genome model) or late (embedded separately,
then joined to the genome embedding). The data preparation, synthetic test data and a first protein encoder are in
place. The early versus late fusion comparison has been designed but not run yet.

| Part | Folder | Status |
|---|---|---|
| Prepare real proteomics | [`proteomics_prep/`](proteomics_prep/) | v0.1.0 on `main`, tested |
| Synthetic test data | SynthTAN v0.1 (not in this repository) | Shared with the team |
| Convert synthetic data for ProLM | [`synthtan_prolm/`](synthtan_prolm/) | On `main`, checked |
| Protein embeddings with ProLM | `proteomics_emb/` (branch `pr_emb`) | First run done, not yet merged |
| Early vs late fusion | – | Designed, not run |

**Preparing real proteomics.** [`proteomics_prep/`](proteomics_prep/) holds five R scripts. They place each protein
in the haploblock that holds its gene's transcription start site, compute tumor minus normal per protein and patient,
and write node and edge CSVs (patients, blocks, proteins, protein-to-block edges) plus a protein × patient matrix.
Each block also carries its haplograph id (`chr21_14215892-14284114`), so proteins can be joined to the cluster nodes
from `1_build_graph.py` by prefix. The scripts come with a made-up example and testthat tests, both passing. See
[`proteomics_prep/README.md`](proteomics_prep/README.md).

**Synthetic test data.** This repository contains no patient data. Tools are developed on SynthTAN v0.1: three
synthetic tumor/normal cohorts (41, 100 and 200 patients) on a pseudo-genome, with 7,000 fake proteins whose values
follow the copy number of their block. Planted signals (an arm loss, breakpoint subgroups, co-loss motifs, protein
trackers and null controls) are listed in a separate answer key, so tools can be checked blind.
[`synthtan_prolm/`](synthtan_prolm/) converts these cohorts to [ProLM](https://github.com/Qiu-Shizheng/ProLM)'s
input format, with random protein embeddings because the fake proteins have no sequences.

**Protein embeddings.** `proteomics_emb/` (branch `pr_emb`) adapts ProLM's `finetune.py` to train all parameters
from scratch and to save one embedding per patient for late fusion. A first run produced 200 × 32 patient embeddings.

**Fusion comparison (next).** Four arms are planned on SynthTAN: genome only, protein only (ProLM), late fusion
(the ProLM patient embedding joined to the genome embedding, which the validator already accepts) and early fusion
(protein values added to the block tokens in the Evo 2 step). Two points from review:

- On SynthTAN v0.1 the genome alone recovers the planted region labels with 98–100% accuracy, so these labels test
  whether proteins are tracked, not whether early beats late fusion. Harder labels are needed for that.
- For a fair comparison, ProLM must be trained inside each cross-validation fold. Its `finetune.py` picks the best
  epoch on its own test split.
